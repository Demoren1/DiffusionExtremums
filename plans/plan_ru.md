# Техническое задание: Диффузионный мета-обучающий алгоритм для генерации весов MLP с индуктивным смещением свертки

## 0. Краткое резюме

### Гипотеза
**Небольшая** диффузионная модель (малое число параметров) выступает в роли мета-обучающего алгоритма / гиперсети (hypernetwork). Обусловленная **идентификатором набора данных (dataset ID)**, она генерирует **веса MLP**. MLP достаточно **велик**, чтобы представлять одномерную свертку (он *не* ограничен по емкости). Обучаясь на множестве различных одномерных наборов данных, истинное правило которых представляет собой локальный, трансляционно-эквивариантный фильтр, компактная диффузионная модель усваивает *индуктивное смещение (inductive bias) сверткоподобного поведения в пространстве весов*. Сгенерированные веса MLP должны хорошо обобщать — приближаться к качеству свертки и превосходить обучение MLP с нуля.

### Ключевая формулировка (не следует путать)
- **MLP НЕ малый**. У него достаточно емкости, чтобы сымитировать свертку. Режим отказа при обучении MLP с нуля — это **отсутствие индуктивного смещения** (переобучение / слабое обобщение), а *не* нехватка емкости.
- **ДИФФУЗИОННАЯ МОДЕЛЬ — та, у которой мало параметров**. Это компактный мета-обучающий алгоритм, который должен обнаружить структуру пространства весов, соответствующую сверткоподобному поведению.
- «Легко решается сверткой, но не MLP с нуля» означает: свертка обобщает лучше при меньшем числе выборок/параметров благодаря **совместному использованию весов (weight sharing) + локальности**. MLP, обучаемый с нуля на одном наборе данных, переобучается / слабо обобщает, несмотря на наличие емкости.

### Протокол сравнения (критерии успеха)
- **(a)** MLP, обученный с нуля на наборе данных X — достаточная емкость, нет смещения → слабое обобщение.
- **(b)** Свертка, обученная на наборе данных X — индуктивное смещение → хорошее обобщение.
- **(c)** Веса MLP, сгенерированные небольшой диффузионной моделью, обусловленной на X — должны приближаться к (b), превосходить (a).

### Принцип дизайна v1
Держать v1 **чистым и обозримым**. Самая чистая проверка основной гипотезы использует **аналитически построенные Toeplitz-веса свертки в качестве диффузионной цели** (Подход A). Это гарантирует, что цель *является* сверткой, устраняет шум подгонки MLP для каждого набора данных из сигнала мета-обучения и изолирует вопрос: *способна ли небольшая диффузионная модель научиться отображать идентификаторы наборов данных → свертко-структурированные векторы весов?* Как только это будет показано, v2 может смягчить требование до обучаемых целей MLP.

## 1. Модуль генерации одномерных данных

### 1.1 Что делает набор данных «легко решаемым сверткой, но не MLP с нуля»
Одномерный регрессионный набор данных $D = \{(x_i, y_i)\}$, где $y = f(x)$ и $f$ — **локальное, трансляционно-эквивариантное** отображение: выход в позиции $p$ зависит только от небольшого окна $x_{p-r}, \dots, x_{p+r}$ через фиксированное ядро $k$, независимо от абсолютной позиции $p$. Свертки кодируют это в точности (совместное использование весов + локальность). Несвязанный MLP *может* подогнать его (емкость), но при ограниченном числе обучающих выборок склонен выучивать нелокальное, привязанное к позиции отображение, которое не обобщается на сдвинутые входы / невидимые позиции.

### 1.2 Длина сигнала и соглашение о свертке
- **Длина входа** $L = 32$ (фиксировано для v1). Каждая выборка $x \in \mathbb{R}^{L}$.
- **Радиус ядра** $r \in \{1, 2, 3\}$ → размер ядра $K = 2r+1 \in \{3, 5, 7\}$.
- **Режим свертки**: `same` (длина выхода = $L$). Использовать zero-padding, чтобы $y \in \mathbb{R}^{L}$.
- Выход: $y_p = \sum_{j=-r}^{r} k_j \, x_{p+j}$ с zero-padding на границах.

### 1.3 Семейства наборов данных (конкретно)
Каждое семейство определяет распределение по ядрам. **Экземпляр набора данных** = одно сэмплированное ядро + конфигурация шума + длина (фиксированное $L$) + количество выборок. Каждый экземпляр получает уникальный **идентификатор набора данных (dataset ID)**.

| Префикс ID | Семейство | Генерация ядра | Почему удобно для свертки / сложно для MLP |
|-----------|--------|-------------------|------------------------------|
| `MA` | Скользящее среднее (low-pass) | $k_j = 1/K$ (box), или Гаусс $\mathcal{N}(0, \sigma_k^2)$, нормированный к сумме 1 | Локальное сглаживание; MLP переобучается на высокочастотном шуме |
| `DIFF` | Разностный / детектор границ | $k = [-1, 0, 1]$ или Sobel-подобный $[-1, 2, -1]$, масштабированный | Локальная производная; привязанный к позиции MLP не справляется со сдвинутыми границами |
| `GAUSS` | Гауссово размытие | $k_j \propto \exp(-j^2/(2\sigma_k^2))$, $\sigma_k \in [0.5, 2.0]$ | Локальное сглаживание с переменной шириной |
| `MATCH` | Локальное сопоставление шаблонов | Разреженное ядро, например $k = [0,0,1,0,0]$ (сдвиг) или $k = [1,-2,1]$ (2-я разность) | Обнаруживает конкретный локальный мотив |
| `RAND` | Случайный локальный FIR | $k \sim \mathcal{N}(0, I_K)$, затем опционально нормированный | Общий локальный линейный фильтр; проверяет мета-обобщение |

### 1.4 Параметризация набора данных и схема ID
Экземпляр набора данных полностью задается кортежем параметров. **Идентификатор набора данных (dataset ID)** — это детерминированный хэш этого кортежа (так что одна и та же конфигурация всегда отображается в один и тот же ID, а обусловливание воспроизводимо).

**Кортеж параметров** (v1):
```
DatasetConfig:
  family:        str   in {MA, DIFF, GAUSS, MATCH, RAND}
  kernel:        float32[K]      # the actual kernel (K = 2r+1)
  radius:        int   in {1,2,3}
  noise_std:     float in {0.0, 0.05, 0.1, 0.2}   # additive Gaussian noise on y
  n_train:       int   in {64, 128, 256}         # training samples per dataset
  n_test:        int   = 512                      # test samples (fixed)
  seed:          int   # base RNG seed for x generation
  L:             int   = 32   (fixed)
```

**Схема ID**: `dataset_id = SHA1(canonical_json(DatasetConfig))[:16]` → строка из 16 шестнадцатеричных символов. Хранится вместе с конфигурацией в реестре. Диффузионная модель обусловливается на этот ID через эмбеддинг (Раздел 3.3).

**Размер корпуса (v1)**: сгенерировать $N_{\text{datasets}} = 2000$ обучающих наборов данных + $300$ отложенных (невидимые ID) для оценки. Наборы данных генерируются **на лету** из конфигураций (нет необходимости хранить сырые массивы, но кэширование в `data/processed/` опционально для воспроизводимости).

### 1.5 Распределение входа
$x \sim$ i.i.d. стандартное нормальное по координатам: $x_p \sim \mathcal{N}(0,1)$. (Просто, делает влияние свертки на обобщение чисто измеримым. v2 может добавить структурированные входы.)

### 1.6 Протокол разбиения train/test
Для каждого экземпляра набора данных:
- **Обучающее множество (Train set)**: `n_train` выборок $(x, y)$ с $y = \text{conv}(x, k) + \epsilon$, $\epsilon \sim \mathcal{N}(0, \text{noise\_std}^2)$.
- **Тестовое множество (Test set)**: `n_test` выборок, взятых из **того же** распределения $x$ (i.i.d. $\mathcal{N}(0,1)$), независимые выборки. Это измеряет **обобщение на новые входы**, а не запоминание.
- **Нет позиционного сдвига между train/test** в v1 (входы i.i.d., поэтому позиции уже перестановочны). Специальный **зонд обобщения при сдвиге** (Раздел 5.5) проверяет отложенное распределение входов (например, $x$ с локализованным всплеском), чтобы нагрузить локальность.

### 1.7 Формы данных и тензорные форматы
Все тензоры `float32`, не зависят от устройства (перемещаются на GPU в цикле обучения).

| Тензор | Форма | Значение |
|--------|-------|---------|
| `x_batch` | `[B, L]` | батч входов |
| `y_batch` | `[B, L]` | батч целевых значений |
| `kernel` | `[K]` | одномерное ядро для набора данных |
| `dataset_id` | `[B]` (int64 индексы) или `[B, id_dim]` (lookup эмбеддинга) | обусловливание |

**DataModule API** (PyTorch):
```python
class DatasetFamily:
    def sample_dataset(self, config: DatasetConfig) -> DatasetInstance  # returns x_train,y_train,x_test,y_test,kernel
    def sample_random_config(self, rng) -> DatasetConfig               # for corpus generation
```

## 2. Построение цели MLP

### 2.1 Рекомендация для v1: Подход A — Аналитические Toeplitz-цели
**Использовать аналитически построенные Toeplitz-веса свертки в качестве цели MLP.**

**Обоснование**:
1. **Гарантирует, что цель ЯВЛЯЕТСЯ сверткой** → сигнал мета-обучения чистый. Диффузионная модель должна научиться производить векторы весов, которые *декодируются в* свертку. Нет смешения из-за качества оптимизации MLP для каждого набора данных.
2. **Устраняет шумный внутренний цикл** (не требуется обучение MLP для каждого набора данных для создания целей), что делает v1 быстрым и воспроизводимым.
3. **Напрямую проверяет гипотезу**: если диффузионная модель способна отобразить идентификатор набора данных → свертко-структурированные веса MLP, которые обобщаются, утверждение об индуктивном смещении в пространстве весов подтверждается.
4. v2 может переключиться на Подход B (обучаемые цели MLP), как только v1 установит пайплайн.

### 2.2 Архитектура MLP (цель генератора весов)
**Однослойный MLP** (с одним скрытым слоем), реализующий одномерную свертку с `same`-паддингом. Мы используем один скрытый слой, потому что свертка $y = W_{\text{conv}} x$ — **линейное** отображение; чтобы представить её как MLP, эффективный линейный оператор MLP должен равняться Toeplitz-матрице свертки. Самая чистая конструкция:

**Архитектура**: `Linear(L, H) → ReLU → Linear(H, L)` с $H = L = 32$.

Подождите — свертка линейна, поэтому двухслойный MLP с ReLU *не* является в точности линейным. Чтобы MLP **в точности представлял свертку**, оставаясь при этом настоящим MLP (нелинейной архитектурой, которая *могла бы* переобучиться), мы используем стандартный трюк: устанавливаем первый слой как **Toeplitz-матрицу**, а второй — как **сквозной проход (pass-through)**, так что композиция линейна, но архитектура сохраняет *емкость* быть не-сверточной.

**Точная конструкция (v1)**:
- `fc1`: `Linear(L, H)`, $H = 64$ (скрытый, шире входа → достаточно емкости).
- `act`: `ReLU`.
- `fc2`: `Linear(H, L)`.

Чтобы этот MLP вычислял в точности $y = T_k x$ (Toeplitz-матрица свертки $T_k \in \mathbb{R}^{L \times L}$), мы **не можем** полагаться на нелинейность ReLU. Вместо этого используем **bypass-конструкцию**:

> Установить `fc1.weight = I_L` (единичная, дополненная до $H$), `fc1.bias = 0`, так что скрытое состояние $h = \text{ReLU}(x)$. Это не линейно.

В этом суть: ReLU MLP не может в точности представить произвольное линейное отображение, если только вход не лежит в неотрицательном ортанте. **Решение для v1**: использовать **линейный MLP** (без активации) в качестве целевой архитектуры, но сохранить его **избыточно параметризованным**, чтобы у него *была емкость* переобучаться (базовый вариант с нуля покажет, что он это делает), тогда как аналитическая Toeplitz-цель делает его сверткой.

**Финальная архитектура MLP для v1 (цель и базовый вариант разделяют её)**:
```
MLPConv:
  fc1: Linear(L, H)   # L=32, H=128  (over-parameterized: H >> L)
  fc2: Linear(H, L)
  # NO nonlinearity in v1 (linear MLP). This is a linear map R^L -> R^L.
  # Capacity: H*(L+1) + L*(H+1) = 128*33 + 32*129 = 4224 + 4128 = 8352 params.
  # A convolution needs only K=2r+1 <= 7 params. The MLP has ~1000x more params.
  # => capacity is NOT the bottleneck; inductive bias is.
```

**Почему линейный (без ReLU) — правильный выбор для v1**:
- Истинное отображение $y = T_k x$ линейно. Линейный MLP может представить его в точности.
- Линейный MLP, обучаемый с нуля на малом числе выборок, — это **неполноранговая / переобученная задача наименьших квадратов** → слабое обобщение (это и есть отказ базового варианта (a)).
- Диффузионная модель должна научиться устанавливать 8352 веса так, чтобы эффективная матрица была **Toeplitz** (всего $K$ степеней свободы) → это и есть усвоение индуктивного смещения свертки в пространстве весов.
- v2 может добавить ReLU и нелинейные истинные отображения.

### 2.3 Toeplitz-отображение: ядро → веса MLP
Для ядра $k \in \mathbb{R}^K$ ($K=2r+1$) построим Toeplitz-матрицу `same`-свертки $T_k \in \mathbb{R}^{L \times L}$:
$$
(T_k)_{p,j} = \begin{cases} k_{j-p+r} & \text{если } 0 \le j-p+r < K \\ 0 & \text{иначе} \end{cases}
$$
(zero-padding на границах).

**Отображение в линейный MLP** так, чтобы `fc2(fc1(x)) = T_k x`:
- **Вариант 1 (прямой, рекомендуется для v1)**: свернуть в один линейный слой. Установить `fc1.weight = I_H[:L]` с добавлением нулей (так что скрытое состояние = $[x; 0]$), `fc1.bias = 0`, и `fc2.weight = T_k` (с дополнительными нулевыми столбцами для $H-L$ неиспользуемых скрытых нейронов), `fc2.bias = 0`. Тогда выход $= T_k x$. Это точно, но «не использует» архитектуру.

- **Вариант 2 (факторизованный, рекомендуется для *осмысленной* цели в пространстве весов)**: факторизовать $T_k = A B$ с $A \in \mathbb{R}^{L \times H}$, $B \in \mathbb{R}^{H \times L}$, $H=128$. Установить `fc1.weight = B`, `fc2.weight = A`. Выбрать факторизацию, **гладкую/структурированную** по $k$, чтобы у диффузионной модели была обучаемая целевая многообразие. Чистый выбор: **факторизация на основе SVD или circulant-embedding**.

**Решение для v1**: Использовать **Вариант 1 (прямая Toeplitz в `fc2`, единичная в `fc1`)** для *построения цели*, потому что это делает целевой вектор весов **простой, детерминированной, гладкой функцией $k$** — идеально для обучения диффузионной модели. Конкретно:

```
fc1.weight:  [I_L ; 0_{(H-L) x L}]   # shape [H, L], identity on top, zeros below
fc1.bias:    0_H
fc2.weight:  [T_k , 0_{L x (H-L)}]   # shape [L, H], Toeplitz block then zeros
fc2.bias:    0_L
```

Это означает, что **единственная нетривиальная, зависящая от $k$ часть цели — это блок $T_k$ в `fc2.weight`** (матрица $L \times L$ = 1024 значения), тогда как единичная/нулевая части постоянны для всех наборов данных. Следовательно, диффузионной модели фактически нужно сгенерировать Toeplitz-матрицу (и скопировать постоянные части). Это удерживает целевое многообразие **низкоразмерным** (параметризованным $K \le 7$ значениями ядра) — в точности то индуктивное смещение, которое мы хотим, чтобы она обнаружила.

### 2.4 Векторизация / формат выравнивания весов
Диффузионная модель генерирует **один плоский вектор** $\theta \in \mathbb{R}^D$, который переформируется в параметры MLP. Определим **канонический, фиксированный порядок**:

```
theta = concat([
    flatten(fc1.weight),   # H*L  = 128*32 = 4096
    flatten(fc1.bias),     # H    = 128
    flatten(fc2.weight),   # L*H  = 32*128 = 4096
    flatten(fc2.bias),     # L    = 32
])
# D = 4096 + 128 + 4096 + 32 = 8352
```

**Спецификация переформирования** (row-major / C-order, соответствует хранению PyTorch `nn.Linear`):
- `fc1.weight` форма `[H, L]` → первые `H*L` элементов, `weight[i,j] = theta[i*L + j]`.
- `fc1.bias` форма `[H]` → следующие `H` элементов.
- `fc2.weight` форма `[L, H]` → следующие `L*H` элементов, `weight[i,j] = theta[offset + i*H + j]`.
- `fc2.bias` форма `[L]` → последние `L` элементов.

Один класс `WeightCodec` обрабатывает `pack(params_dict) -> theta` и `unpack(theta) -> params_dict` и `instantiate(theta) -> MLPConv`. **D = 8352** — это размерность данных диффузионной модели.

### 2.5 Нормализация весов (критично для диффузии)
Диффузия предполагает данные $\approx \mathcal{N}(0,1)$. Сырые веса MLP таковыми не являются. Мы **стандартизируем целевой вектор весов**, используя статистики, вычисленные один раз по обучающему корпусу:

- Вычислить среднее по каждому измерению $\mu \in \mathbb{R}^D$ и стандартное отклонение $\sigma \in \mathbb{R}^D$ по всем целевым $\theta$ в обучающем корпусе.
- Диффузионная модель работает с $z = (\theta - \mu) / \sigma$.
- Во время генерации декодировать $\hat\theta = \sigma \odot \hat z + \mu$.
- **Важно**: из-за единичной/нулевой структуры многие размерности $\theta$ **постоянны** (std = 0). Для них установить $\sigma = 1$ и $\mu = $ это константа, так что $z = 0$ там. Диффузионная модель усваивает, что они тривиальны (всегда 0 в $z$-пространстве). Это нормально и даже помогает (снижает эффективную размерность).

Сохранить $\mu, \sigma$ вместе с чекпойнтом модели.

## 3. Архитектура диффузионной гиперсети

### 3.1 Обзор
**DDPM** над пространством весов: размерность данных $D = 8352$. Сеть денойзинга $\epsilon_\phi(z_t, t, \text{cond})$ предсказывает шум, добавленный на шаге $t$, обусловленная на идентификаторе набора данных. Модель намеренно **маленькая** (в этом весь смысл).

### 3.2 Прямой / обратный процесс (стандартный DDPM)
- **Шумовое расписание (noise schedule)**: линейное $\beta_t \in [1\text{e-}4, 0.02]$, $T = 1000$ шагов. $\alpha_t = 1-\beta_t$, $\bar\alpha_t = \prod_{s\le t}\alpha_s$.
- **Прямой (Forward)**: $z_t = \sqrt{\bar\alpha_t}\, z_0 + \sqrt{1-\bar\alpha_t}\, \epsilon$, $\epsilon \sim \mathcal{N}(0, I_D)$.
- **Обратный (сэмплирование)**: стандартное ancestry-сэмплирование DDPM из $z_T \sim \mathcal{N}(0, I_D)$ с использованием $\epsilon_\phi$.
- **Loss**: $\mathcal{L} = \mathbb{E}_{t, z_0, \epsilon} \| \epsilon - \epsilon_\phi(z_t, t, \text{cond}) \|_2^2$ (простой MSE, без перевзвешивания в v1).

### 3.3 Обусловливание на идентификаторе набора данных
Идентификатор набора данных — это 16-символьная шестнадцатеричная строка. Для обусловливания используем **таблицу эмбеддингов**:
- Ведем реестр, отображающий каждый идентификатор набора данных → целочисленный индекс $i \in \{0, \dots, N_{\text{datasets}}-1\}$.
- `id_embedding = nn.Embedding(num_embeddings=N_datasets, embedding_dim=128)`.
- Этот эмбеддинг **обучается совместно** с денойзером. Это канал, через который модель «знает», какой набор данных (следовательно, какое ядро) генерировать.
- Для **отложенных идентификаторов наборов данных** (невидимых при обучении) эмбеддинга не существует. Оценка v1 на отложенных ID использует **fallback**: обусловиться на **ближайшем обучающем идентификаторе набора данных** по расстоянию в пространстве ядер, ИЛИ (чище) добавить **энкодер дескриптора набора данных**: небольшой MLP, отображающий **фиксированный вектор признаков конфигурации** (например, `[family_onehot, kernel_values, radius, noise_std]`) → обусловливающий эмбеддинг. Это обеспечивает zero-shot обобщение на невидимые ID. **Решение для v1**: реализовать **энкодер признаков конфигурации** как основной путь обусловливания (чтобы отложенные ID работали), с путем таблицы эмбеддингов как опциональным абляционным.

**Вектор признаков конфигурации для обусловливания** (dim = $4 + K_{\max} + 1$):
```
cond_features = concat([
    family_onehot,          # 5
    kernel_padded,          # K_max = 7 (zero-padded to max radius)
    radius,                # 1
    noise_std,              # 1
])
# dim = 5 + 7 + 1 + 1 = 14
```
`cond_encoder = MLP([14, 64, 128])` → 128-мерный обусловливающий эмбеддинг $c$.

### 3.4 Архитектура сети денойзинга (маленькая)
Денойзер принимает $(z_t \in \mathbb{R}^D, t, c)$ и выдает $\hat\epsilon \in \mathbb{R}^D$. Держим её **маленькой и на основе MLP** (пространство весов не имеет пространственной структуры, которую мы используем в v1; структура — в *целевом многообразии*, которое модель должна обнаружить).

**Архитектура** (компактный MLP с FiLM-обусловливанием):
```
DenoiserNet:
  time_emb: SinusoidalTimeEmbedding(dim=128) -> Linear(128,128) -> SiLU -> Linear(128,128)
  cond_emb: (from cond_encoder) c in R^128
  input: z_t in R^D (D=8352)

  # FiLM modulation per layer
  h = Linear(D, 256)(z_t)
  for block in [256, 256, 256]:
      h = Linear(prev, block)(h) + time_proj(block) + cond_proj(block)   # additive FiLM (v1: additive, not scale-shift, for simplicity)
      h = SiLU(h)
  out = Linear(256, D)(h)
```

**Конкретные слои**:
- `fc_in`: Linear(8352, 256)
- 3× residual-подобных блока: Linear(256,256) + time/cond bias, SiLU.
- `fc_out`: Linear(256, 8352)
- Проекции времени и cond: Linear(128, 256) каждая, добавляются как bias перед активацией.

**Целевое число параметров**:
- `fc_in`: 8352×256 + 256 ≈ 2.14M
- 3 блока: 3×(256×256 + 256) ≈ 0.20M
- time/cond proj: 2×(128×256 + 256) ≈ 0.066M
- `fc_out`: 256×8352 + 8352 ≈ 2.14M
- `cond_encoder`: 14×64 + 64×128 + ... ≈ 0.017M
- **Итого ≈ 4.6M параметров**.

**Проверка «малости»**: MLP, который она генерирует, имеет 8352 параметра; диффузионная модель ~4.6M. Диффузионная модель больше, чем *один* MLP, но она **мала относительно пространства, которое моделирует**, и, что критично, она разделяется между **2000 наборов данных** — так что на один набор данных приходится ~2300 параметров, *меньше*, чем у MLP, который она генерирует. Формулировка «мало параметров» относится к тому, что модель является **компактным разделяемым мета-обучающим алгоритмом**, а не буквально меньше одной цели. (Если для абляции v1 требуется строго меньший денойзер, уменьшить скрытый слой до 128 → ~1.3M параметров; задокументировано как ручка абляции.)

### 3.5 Эмбеддинг шага времени
Стандартный синусоидальный:
$$
\text{te}(t)_{2i} = \sin(t \cdot 10000^{-2i/d}), \quad \text{te}(t)_{2i+1} = \cos(\cdot)
$$
с $d=128$, затем 2-слойный MLP до 128. Сэмплирование $t \sim \mathcal{U}\{1, T\}$.

### 3.6 Сэмплирование
Стандартное ancestry-сэмплирование DDPM на 1000 шагов (v1). Опционально DDIM на 50 шагов для быстрой оценки (задокументировано, не требуется для критериев успеха v1).

## 4. Цикл обучения

### 4.1 Обучающие данные для диффузионной модели
Для каждой конфигурации набора данных в обучающем корпусе:
1. Сэмплировать/зафиксировать ядро $k$ (из конфигурации).
2. Построить Toeplitz-цель — веса MLP $\theta$ (Раздел 2.3).
3. Упаковать в $\theta \in \mathbb{R}^{8352}$ (Раздел 2.4).
4. Стандартизировать: $z_0 = (\theta - \mu)/\sigma$ (Раздел 2.5).
5. Вычислить признаки обусловливания из конфигурации (Раздел 3.3).

**Датасет для обучения диффузии** = список пар `(config, z_0)`. Генерируется один раз (корпус из 2000) и переиспользуется каждую эпоху. Опционально аугментация пересэмплированием ядер внутри семейства каждую эпоху (v1: фиксированный корпус для воспроизводимости; аугментация — ручка v2).

### 4.2 Целевая функция обучения диффузии
Стандартный MSE предсказания шума DDPM:
$$
\mathcal{L}(\phi) = \mathbb{E}_{\text{dataset} \sim \text{corpus}} \mathbb{E}_{t \sim \mathcal{U}(1,T)} \mathbb{E}_{\epsilon \sim \mathcal{N}(0,I)} \left\| \epsilon - \epsilon_\phi\!\left(\sqrt{\bar\alpha_t}\, z_0 + \sqrt{1-\bar\alpha_t}\,\epsilon,\; t,\; \text{cond}(\text{config})\right) \right\|_2^2
$$

### 4.3 Расписание обучения, оптимизатор, гиперпараметры
| Пункт | Значение |
|------|-------|
| Оптимизатор | AdamW |
| Learning rate | $1\text{e-}3$, косинусный спад до $1\text{e-}5$ |
| Weight decay | $1\text{e-}2$ |
| Batch size | 256 наборов данных на батч (каждый дает один $z_0$) |
| Эпохи | 1000 по корпусу (корпус = 2000 → ~128k шагов) |
| EMA на веса денойзера | decay 0.9999 (использовать EMA-модель для сэмплирования) |
| Gradient clipping | max norm 1.0 |
| $T$ (шаги диффузии) | 1000 |
| $\beta$ расписание | линейное $[1\text{e-}4, 0.02]$ |
| Точность | float32 (v1); float16 mixed precision опционально |
| Логирование | TensorBoard: loss, per-dim weight std, EMA loss |

### 4.4 Обработка масштаба / дисперсии весов
- Построчная (per-dimension) стандартизация (Раздел 2.5) обеспечивает $z_0 \approx$ единичная дисперсия (где не постоянно).
- Постоянные размерности (блоки identity/zeros) отображаются ровно в 0 → тривиально для модели.
- Никакой нормализации весов внутри слоев денойзера, кроме стандартизации.

### 4.5 Псевдокод цикла обучения
```
for epoch in range(1000):
    for batch_configs in DataLoader(corpus, batch_size=256, shuffle=True):
        z0 = pack_and_standardize(batch_configs)          # [B, D]
        cond = cond_encoder(features(batch_configs))      # [B, 128]
        t = randint(1, T, [B])
        eps = randn([B, D])
        zt = sqrt(bar_alpha[t]) * z0 + sqrt(1-bar_alpha[t]) * eps
        eps_hat = denoiser(zt, t, cond)
        loss = mse(eps, eps_hat)
        optimizer.zero_grad(); loss.backward(); clip_grad_norm_(1.0); optimizer.step()
        ema.update(denoiser)
    cosine_lr.step()
    if epoch % 50 == 0: sample_and_log()   # generate a few, decode, eval on test sets
```

## 5. Протокол оценки

### 5.1 Базовые варианты
Для каждого оценочного набора данных $X$ (конфигурация + его разбиение train/test):

**(a) MLP с нуля**:
- Инстанцировать `MLPConv` (8352 параметра, линейный, избыточно параметризованный).
- Обучать с AdamW (lr $1\text{e-}3$, 2000 шагов) на `n_train` выборках набора данных, loss MSE по $y$.
- Записать train MSE и **test MSE**. Это базовый вариант без индуктивного смещения → ожидается высокий test MSE (переобучение), когда `n_train` мало.

**(b) Свертка**:
- Одномерный conv-слой с размером ядра $K$ (*истинный* размер ядра семейства, но **ядро обучается по train-данным**, не дается).
- Обучать с AdamW на `n_train` выборках.
- Записать train/test MSE. Это базовый вариант с индуктивным смещением → ожидается низкий test MSE.
- Также сообщить **oracle conv** (ядро = истинное $k$) как нижнюю границу.

**(c) Диффузионно-сгенерированный MLP**:
- Сэмплировать $\hat z_0 \sim$ диффузия, обусловленная на конфигурации $X$ (EMA-денойзер, 1000 шагов).
- Декодировать $\hat\theta = \sigma \odot \hat z_0 + \mu$, инстанцировать `MLPConv`.
- **Без дальнейшего обучения** (zero-shot генерация весов). Оценить test MSE напрямую.
- Также сообщить **best-of-$N$** (сэмплировать $N=8$, выбрать с наименьшим train MSE) как практический вариант.

### 5.2 Метрики
| Метрика | Определение |
|--------|------------|
| Test MSE | $\frac{1}{|\text{test}|}\sum \|f(x) - y\|^2$ (на выборку, усреднено по $L$ позициям) |
| Разрыв обобщения | train MSE − test MSE |
| Относительный test MSE | test MSE / test MSE oracle-conv (1.0 = идеальная свертка) |
| Эффективность по выборкам | кривая test MSE vs. `n_train` (перебор `n_train` ∈ {16,32,64,128,256}) |
| Число параметров | MLP: 8352; conv: $K$; диффузия: ~4.6M (разделяемые) |
| Оценка Toeplitz-ности | $\| \hat T - \text{Toeplitzify}(\hat T)\|_F / \|\hat T\|_F$ сгенерированного блока `fc2` (измеряет, являются ли сгенерированные веса свертко-структурированными) |

### 5.3 Отложенные идентификаторы наборов данных (мета-обобщение)
- **Отложенный корпус**: 300 конфигураций с ID, никогда не виденными при обучении.
- Для каждой запустить (a), (b), (c). Энкодер признаков конфигурации (Раздел 3.3) обеспечивает zero-shot генерацию для них.
- Сообщить агрегированный test MSE (среднее ± std по отложенным наборам данных), по семействам.

### 5.4 Критерии успеха (количественные пороги для v1)
1. **(c) превосходит (a)**: test MSE диффузионно-сгенерированного MLP < test MSE MLP с нуля на **≥ 80%** отложенных наборов данных при `n_train = 64`.
2. **(c) приближается к (b)**: test MSE диффузии ≤ 1.5× test MSE свертки на **≥ 50%** отложенных наборов данных.
3. **Toeplitz-ность**: оценка Toeplitz-ности сгенерированного блока `fc2` **≤ 0.2** (т.е. сгенерированные веса в основном свертко-структурированы).
4. **Обобщение на отложенных**: критерии 1–2 выполняются на отложенных ID, а не только на обучающих ID.

### 5.5 Зонд обобщения при сдвиге (стресс-тест локальности)
- Построить пробный вход $x^*$ с **локализованным всплеском** (нули, кроме гауссова всплеска в случайной позиции).
- Вычислить $f(x^*)$ для (a), (b), (c). Свертка дает сдвинутый всплеск; переобученный MLP дает мусор вне обученных позиций.
- Метрика: корреляция $f(x^*)$ со сдвинутым истинным всплеском, по позициям всплеска.

### 5.6 План визуализации
1. **Кривые loss**: loss обучения диффузии (сырой + EMA) vs. шаги.
2. **Сгенерированные vs. целевые веса**: для выборочных наборов данных, тепловая карта $\hat T$ vs. $T_k$ (блок `fc2`), и scatter $\hat\theta$ vs. $\theta$.
3. **Toeplitz-ность в ходе обучения**: оценка Toeplitz-ности vs. эпоха (должна убывать).
4. **Эффективность по выборкам**: test MSE vs. `n_train` для (a), (b), (c) — три кривые.
5. **Столбчатая диаграмма по семействам**: test MSE (a)/(b)/(c), сгруппированные по семействам.
6. **Зонд сдвига**: наложение $f(x^*)$ для трех методов vs. истинный сдвинутый всплеск.
7. **Анализ эмбеддингов/обусловливания**: t-SNE выходов `cond_encoder`, окрашенных по семействам (кодирует ли обусловливание структуру семейств?).

Все графики сохраняются в `figures/`; метрики + сырые массивы в `results/`.

## 8. Сводка ключевых проектных решений

| Решение | Выбор | Обоснование |
|----------|--------|-----------|
| Источник целевых весов | **Аналитическая Toeplitz (Подход A)** | Чистый сигнал мета-обучения; цель ЯВЛЯЕТСЯ сверткой; нет шума внутреннего цикла |
| Архитектура MLP | Линейный, $L=32, H=128$, 8352 параметра | Избыточно параметризованный (емкость ✓), но линейный, так что Toeplitz точен; с нуля переобучается (смещение ✗) |
| Toeplitz-отображение | Единичная в `fc1`, $T_k$ в `fc2` | Целевое многообразие низкоразмерно (≤7 степеней свободы ядра); легко для обучения диффузии |
| Векторизация весов | Фиксированный C-order: fc1.w, fc1.b, fc2.w, fc2.b | Детерминированный pack/unpack |
| Нормализация весов | Построчная стандартизация; постоянные размерности → 0 | Диффузия предполагает N(0,1); тривиальные размерности снижают эффективную размерность |
| Обусловливание | Энкодер признаков конфигурации (14-мер → 128) | Обеспечивает zero-shot на отложенных ID; таблица эмбеддингов как абляция |
| Диффузия | DDPM, $T=1000$, линейный $\beta[1\text{e-}4, 0.02]$, loss MSE | Стандартная, простая, обозримая |
| Денойзер | Компактный MLP + FiLM, ~4.6M параметров | Малый разделяемый мета-обучающий алгоритм; ~2300 параметров/набор данных < 8352 параметров MLP |
| Корпус | 2000 обучающих + 300 отложенных наборов данных | Достаточно для изучения многообразия ядро→веса; отложенные проверяют мета-обобщение |
| Порог успеха | (c) превосходит (a) на ≥80%, ≤1.5× (b) на ≥50%, Toeplitz-ность ≤0.2 | Конкретные, фальсифицируемые критерии v1 |

## 9. Риски и меры противодействия

| Риск | Меры противодействия |
|------|-----------|
| Диффузионная модель запоминает обучающие ID, не справляется на отложенных | Обусловливание по признакам конфигурации (не таблица ID); оценка на отложенных — основная метрика |
| Сгенерированные веса недостаточно Toeplitz | Метрика Toeplitz-ности мониторится; можно добавить loss Toeplitz-регуляризации в v2 |
| 8352-мерная диффузия медленная/нестабильная | Построчная стандартизация; EMA; начать с абляции hidden=128; DDIM для быстрой оценки |
| Базовый вариант MLP с нуля не переобучается (явление отсутствует) | Валидировать на Этапе 2 до построения диффузии; настроить `n_train` для обеспечения переобучения |
| Линейный MLP делает историю «индуктивного смещения» менее драматичной | v1 изолирует вопрос о структуре пространства весов; v2 добавляет ReLU + нелинейные отображения для более сильной истории |

## 10. Расширения v2 (вне рамок v1, задокументировано для преемственности)
- Подход B: обучаемые веса MLP как цели диффузии (подгонка MLP для каждого набора данных).
- Нелинейные истинные отображения + ReLU MLP.
- Структурированные распределения входов (авторегрессионные, локализованные всплески как *обучающее* распределение).
- Больший $L$ (64, 128) и более глубокие MLP.
- DDIM / fast-сэмплирование consistency-моделью.
- Toeplitz-регуляризованный loss диффузии для явного навязывания свертко-структуры.
- Кросс-семейственное мета-обобщение (обучение на 4 семействах, тест на 1 отложенном семействе).
