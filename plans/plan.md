# Technical Specification: Diffusion Meta-Learner for Convolution-Inductive-Bias MLP Weight Generation

## 0. Executive Summary

### Hypothesis
A **small** diffusion model (few parameters) acts as a meta-learner / hypernetwork. Conditioned on a **dataset ID**, it generates the **weights of an MLP**. The MLP is **large enough** to represent a 1D convolution (it is *not* capacity-limited). By training across many different 1D datasets whose ground-truth rule is a local, translation-equivariant filter, the compact diffusion model learns the *inductive bias of convolution-like behavior in weight space*. The generated MLP weights should generalize well — approaching convolution performance and beating from-scratch MLP training.

### Key Framing (must not be confused)
- The **MLP is NOT small**. It has enough capacity to simulate a convolution. The failure mode of from-scratch MLP training is **lack of inductive bias** (overfitting / poor generalization), *not* lack of capacity.
- The **DIFFUSION MODEL is the one with few parameters**. It is the compact meta-learner that must discover the structure of weight space corresponding to convolution-like behavior.
- "Easily solved by convolution but not by from-scratch MLP" means: convolution generalizes better with fewer samples/parameters due to **weight sharing + locality**. A from-scratch MLP on a single dataset overfits / generalizes poorly despite having capacity.

### Comparison Protocol (success criteria)
- **(a)** MLP trained from scratch on dataset X — enough capacity, no bias → poor generalization.
- **(b)** Convolution trained on dataset X — inductive bias → good generalization.
- **(c)** MLP weights generated by the small diffusion model conditioned on X — should approach (b), beat (a).

### v1 Design Principle
Keep v1 **clean and tractable**. The cleanest test of the core hypothesis uses **analytically constructed Toeplitz convolution weights as the diffusion target** (Approach A). This guarantees the target *is* a convolution, removes per-dataset MLP-fitting noise from the meta-learning signal, and isolates the question: *can a small diffusion model learn to map dataset IDs → convolution-structured weight vectors?* Once this is demonstrated, v2 can relax to learned MLP targets.

## 1. 1D Data Generation Module

### 1.1 What makes a dataset "easily solved by convolution but not by from-scratch MLP"
A 1D regression dataset $D = \{(x_i, y_i)\}$ where $y = f(x)$ and $f$ is a **local, translation-equivariant** mapping: the output at position $p$ depends only on a small window $x_{p-r}, \dots, x_{p+r}$ via a fixed kernel $k$, independent of absolute position $p$. Convolutions encode this exactly (weight sharing + locality). An unconstrained MLP *can* fit it (capacity) but, with limited training samples, tends to learn a non-local, position-specific mapping that does not generalize to shifted inputs / unseen positions.

### 1.2 Signal length and convolution convention
- **Input length** $L = 32$ (fixed for v1). Each sample $x \in \mathbb{R}^{L}$.
- **Kernel radius** $r \in \{1, 2, 3\}$ → kernel size $K = 2r+1 \in \{3, 5, 7\}$.
- **Convolution mode**: `same` (output length = $L$). Use zero-padding so $y \in \mathbb{R}^{L}$.
- Output: $y_p = \sum_{j=-r}^{r} k_j \, x_{p+j}$ with zero-padding at boundaries.

### 1.3 Dataset families (concrete)
Each family defines a distribution over kernels. A **dataset instance** = one sampled kernel + noise config + length (fixed $L$) + sample count. Each instance gets a unique **dataset ID**.

| ID prefix | Family | Kernel generation | Why conv-friendly / MLP-hard |
|-----------|--------|-------------------|------------------------------|
| `MA` | Moving average (low-pass) | $k_j = 1/K$ (box), or Gaussian $\mathcal{N}(0, \sigma_k^2)$ normalized to sum 1 | Local smoothing; MLP overfits high-freq noise |
| `DIFF` | Difference / edge detector | $k = [-1, 0, 1]$ or Sobel-like $[-1, 2, -1]$, scaled | Local derivative; position-specific MLP fails on shifted edges |
| `GAUSS` | Gaussian blur | $k_j \propto \exp(-j^2/(2\sigma_k^2))$, $\sigma_k \in [0.5, 2.0]$ | Local smoothing with varying width |
| `MATCH` | Local pattern matching | Sparse kernel, e.g. $k = [0,0,1,0,0]$ (shift) or $k = [1,-2,1]$ (2nd diff) | Detects a specific local motif |
| `RAND` | Random local FIR | $k \sim \mathcal{N}(0, I_K)$, then optionally normalized | General local linear filter; tests meta-generalization |

### 1.4 Dataset parameterization and ID scheme
A dataset instance is fully specified by a parameter tuple. The **dataset ID** is a deterministic hash of this tuple (so the same config always maps to the same ID, and conditioning is reproducible).

**Parameter tuple** (v1):
```
DatasetConfig:
  family:        str   in {MA, DIFF, GAUSS, MATCH, RAND}
  kernel:        float32[K]      # the actual kernel (K = 2r+1)
  radius:        int   in {1,2,3}
  noise_std:     float in {0.0, 0.05, 0.1, 0.2}   # additive Gaussian noise on y
  n_train:       int   in {64, 128, 256}         # training samples per dataset
  n_test:        int   = 512                      # test samples (fixed)
  seed:          int   # base RNG seed for x generation
  L:             int   = 32   (fixed)
```

**ID scheme**: `dataset_id = SHA1(canonical_json(DatasetConfig))[:16]` → 16-hex-char string. Stored alongside config in a registry. The diffusion model conditions on this ID via an embedding (Section 3.3).

**Corpus size (v1)**: generate $N_{\text{datasets}} = 2000$ training datasets + $300$ held-out (unseen IDs) for evaluation. Datasets are generated **on-the-fly** from configs (no need to store raw arrays, but caching to `data/processed/` is optional for reproducibility).

### 1.5 Input distribution
$x \sim$ i.i.d. standard normal per coordinate: $x_p \sim \mathcal{N}(0,1)$. (Simple, makes the convolution's effect on generalization clean to measure. v2 may add structured inputs.)

### 1.6 Train/test split protocol
For each dataset instance:
- **Train set**: `n_train` samples $(x, y)$ with $y = \text{conv}(x, k) + \epsilon$, $\epsilon \sim \mathcal{N}(0, \text{noise\_std}^2)$.
- **Test set**: `n_test` samples drawn from the **same** $x$ distribution (i.i.d. $\mathcal{N}(0,1)$), independent draws. This measures **generalization to new inputs**, not memorization.
- **No position shift between train/test** in v1 (inputs are i.i.d. so positions are already exchangeable). A dedicated **shift-generalization probe** (Section 5.5) tests a held-out input distribution (e.g., $x$ with a localized bump) to stress locality.

### 1.7 Data shapes and tensor formats
All tensors `float32`, device-agnostic (moved to GPU in training loop).

| Tensor | Shape | Meaning |
|--------|-------|---------|
| `x_batch` | `[B, L]` | batch of inputs |
| `y_batch` | `[B, L]` | batch of targets |
| `kernel` | `[K]` | 1D kernel for the dataset |
| `dataset_id` | `[B]` (int64 indices) or `[B, id_dim]` (embedding lookup) | conditioning |

**DataModule API** (PyTorch):
```python
class DatasetFamily:
    def sample_dataset(self, config: DatasetConfig) -> DatasetInstance  # returns x_train,y_train,x_test,y_test,kernel
    def sample_random_config(self, rng) -> DatasetConfig               # for corpus generation
```

## 2. MLP Target Construction

### 2.1 Recommendation for v1: Approach A — Analytic Toeplitz targets
**Use analytically constructed Toeplitz convolution weights as the MLP target.**

**Justification**:
1. **Guarantees the target IS a convolution** → the meta-learning signal is clean. The diffusion model must learn to produce weight vectors that *decode to* a convolution. No confound from per-dataset MLP optimization quality.
2. **Removes a noisy inner loop** (no per-dataset MLP training needed to create targets), making v1 fast and reproducible.
3. **Directly tests the hypothesis**: if the diffusion model can map dataset ID → convolution-structured MLP weights that generalize, the inductive-bias-in-weight-space claim is supported.
4. v2 can switch to Approach B (learned MLP targets) once v1 establishes the pipeline.

### 2.2 MLP architecture (the weight generator's target)
A **single-hidden-layer MLP** that implements a `same`-padding 1D convolution. We use one hidden layer because a convolution $y = W_{\text{conv}} x$ is a **linear** map; representing it as an MLP requires the MLP's effective linear operator to equal the Toeplitz convolution matrix. The cleanest construction:

**Architecture**: `Linear(L, H) → ReLU → Linear(H, L)` with $H = L = 32$.

Wait — a convolution is linear, so a 2-layer MLP with ReLU is *not* exactly linear. To make the MLP **exactly represent the convolution** while still being a genuine MLP (nonlinear architecture that *could* overfit), we use the standard trick: set the first layer to a **Toeplitz matrix** and the second layer to **pass-through** so the composition is linear, but the architecture retains the *capacity* to be non-convolutional.

**Exact construction (v1)**:
- `fc1`: `Linear(L, H)`, $H = 64$ (hidden, wider than input → enough capacity).
- `act`: `ReLU`.
- `fc2`: `Linear(H, L)`.

To make this MLP compute exactly $y = T_k x$ (Toeplitz convolution matrix $T_k \in \mathbb{R}^{L \times L}$), we **cannot** rely on ReLU nonlinearity. Instead we use the **bypass construction**:

> Set `fc1.weight = I_L` (identity, padded to $H$), `fc1.bias = 0`, so hidden $h = \text{ReLU}(x)$. This is not linear.

This is the crux: a ReLU MLP cannot exactly represent an arbitrary linear map unless the input is in the non-negative orthant. **Resolution for v1**: use a **linear MLP** (no activation) as the target architecture, but keep it **over-parameterized** so it *has the capacity* to overfit (the from-scratch baseline will demonstrate it does), while the analytic Toeplitz target makes it a convolution.

**Final v1 MLP architecture (target & baseline share this)**:
```
MLPConv:
  fc1: Linear(L, H)   # L=32, H=128  (over-parameterized: H >> L)
  fc2: Linear(H, L)
  # NO nonlinearity in v1 (linear MLP). This is a linear map R^L -> R^L.
  # Capacity: H*(L+1) + L*(H+1) = 128*33 + 32*129 = 4224 + 4128 = 8352 params.
  # A convolution needs only K=2r+1 <= 7 params. The MLP has ~1000x more params.
  # => capacity is NOT the bottleneck; inductive bias is.
```

**Why linear (no ReLU) is the right v1 choice**:
- The ground-truth map $y = T_k x$ is linear. A linear MLP can represent it exactly.
- A linear MLP trained from scratch on few samples is a **rank-deficient / overfit least-squares** problem → poor generalization (this is the baseline (a) failure).
- The diffusion model must learn to set the 8352 weights so the effective matrix is **Toeplitz** (only $K$ degrees of freedom) → this is precisely learning the convolution inductive bias in weight space.
- v2 can add ReLU and nonlinear ground-truth maps.

### 2.3 Toeplitz mapping: kernel → MLP weights
Given kernel $k \in \mathbb{R}^K$ ($K=2r+1$), build the `same`-convolution Toeplitz matrix $T_k \in \mathbb{R}^{L \times L}$:
$$
(T_k)_{p,j} = \begin{cases} k_{j-p+r} & \text{if } 0 \le j-p+r < K \\ 0 & \text{otherwise} \end{cases}
$$
(zero-padding at boundaries).

**Map into the linear MLP** so that `fc2(fc1(x)) = T_k x`:
- **Option 1 (direct, recommended v1)**: collapse to a single linear layer. Set `fc1.weight = I_H[:L]` stacked with zeros (so hidden = $[x; 0]$), `fc1.bias = 0`, and `fc2.weight = T_k` (with extra zero columns for the $H-L$ unused hidden units), `fc2.bias = 0`. Then output $= T_k x$. This is exact but "wastes" the architecture.

- **Option 2 (factorized, recommended for a *meaningful* weight-space target)**: factor $T_k = A B$ with $A \in \mathbb{R}^{L \times H}$, $B \in \mathbb{R}^{H \times L}$, $H=128$. Set `fc1.weight = B`, `fc2.weight = A`. Choose a factorization that is **smooth/structured** in $k$ so the diffusion model has a learnable target manifold. A clean choice: **SVD-based or circulant-embedding factorization**.

**v1 decision**: Use **Option 1 (direct Toeplitz in `fc2`, identity in `fc1`)** for the *target construction*, because it makes the target weight vector a **simple, deterministic, smooth function of $k$** — ideal for the diffusion model to learn. Specifically:

```
fc1.weight:  [I_L ; 0_{(H-L) x L}]   # shape [H, L], identity on top, zeros below
fc1.bias:    0_H
fc2.weight:  [T_k , 0_{L x (H-L)}]   # shape [L, H], Toeplitz block then zeros
fc2.bias:    0_L
```

This means the **only non-trivial, $k$-dependent part of the target is the $T_k$ block in `fc2.weight`** (an $L \times L$ matrix = 1024 values), while the identity/zeros are constant across all datasets. The diffusion model therefore effectively needs to generate the Toeplitz matrix (and copy the constant parts). This keeps the target manifold **low-dimensional** (parametrized by $K \le 7$ kernel values) — exactly the inductive bias we want it to discover.

### 2.4 Weight vectorization / flattening format
The diffusion model generates a **single flat vector** $\theta \in \mathbb{R}^D$ that is reshaped into the MLP's parameters. Define a **canonical, fixed ordering**:

```
theta = concat([
    flatten(fc1.weight),   # H*L  = 128*32 = 4096
    flatten(fc1.bias),     # H    = 128
    flatten(fc2.weight),   # L*H  = 32*128 = 4096
    flatten(fc2.bias),     # L    = 32
])
# D = 4096 + 128 + 4096 + 32 = 8352
```

**Reshape spec** (row-major / C-order, matching PyTorch `nn.Linear` storage):
- `fc1.weight` shape `[H, L]` → first `H*L` entries, `weight[i,j] = theta[i*L + j]`.
- `fc1.bias` shape `[H]` → next `H` entries.
- `fc2.weight` shape `[L, H]` → next `L*H` entries, `weight[i,j] = theta[offset + i*H + j]`.
- `fc2.bias` shape `[L]` → last `L` entries.

A single `WeightCodec` class handles `pack(params_dict) -> theta` and `unpack(theta) -> params_dict` and `instantiate(theta) -> MLPConv`. **D = 8352** is the diffusion model's data dimension.

### 2.5 Weight normalization (critical for diffusion)
Diffusion assumes data $\approx \mathcal{N}(0,1)$. Raw MLP weights are not. We **standardize the target weight vector** using statistics computed once over the training corpus:

- Compute per-dimension mean $\mu \in \mathbb{R}^D$ and std $\sigma \in \mathbb{R}^D$ over all target $\theta$ in the training corpus.
- The diffusion model operates on $z = (\theta - \mu) / \sigma$.
- At generation time, decode $\hat\theta = \sigma \odot \hat z + \mu$.
- **Important**: because of the identity/zeros structure, many dimensions of $\theta$ are **constant** (std = 0). For those, set $\sigma = 1$ and $\mu = $ that constant, so $z = 0$ there. The diffusion model learns these are trivial (always 0 in $z$-space). This is fine and actually helps (reduces effective dimensionality).

Store $\mu, \sigma$ alongside the model checkpoint.

## 3. Diffusion Hypernetwork Architecture

### 3.1 Overview
A **DDPM** over weight space: data dimension $D = 8352$. The denoising network $\epsilon_\phi(z_t, t, \text{cond})$ predicts the noise added at timestep $t$, conditioned on the dataset ID. The model is deliberately **small** (the whole point).

### 3.2 Forward / reverse process (standard DDPM)
- **Noise schedule**: linear $\beta_t \in [1\text{e-}4, 0.02]$, $T = 1000$ timesteps. $\alpha_t = 1-\beta_t$, $\bar\alpha_t = \prod_{s\le t}\alpha_s$.
- **Forward**: $z_t = \sqrt{\bar\alpha_t}\, z_0 + \sqrt{1-\bar\alpha_t}\, \epsilon$, $\epsilon \sim \mathcal{N}(0, I_D)$.
- **Reverse (sampling)**: standard DDPM ancestral sampling from $z_T \sim \mathcal{N}(0, I_D)$ using $\epsilon_\phi$.
- **Loss**: $\mathcal{L} = \mathbb{E}_{t, z_0, \epsilon} \| \epsilon - \epsilon_\phi(z_t, t, \text{cond}) \|_2^2$ (simple MSE, no reweighting in v1).

### 3.3 Conditioning on dataset ID
The dataset ID is a 16-hex string. For conditioning we use an **embedding table**:
- Maintain a registry mapping each dataset ID → integer index $i \in \{0, \dots, N_{\text{datasets}}-1\}$.
- `id_embedding = nn.Embedding(num_embeddings=N_datasets, embedding_dim=128)`.
- This embedding is **learned jointly** with the denoiser. It is the channel through which the model "knows" which dataset (hence which kernel) to generate.
- For **held-out dataset IDs** (unseen at train time), the embedding does not exist. v1 evaluation on held-out IDs uses a **fallback**: condition on the **nearest training dataset ID** by kernel-space distance, OR (cleaner) add a **dataset-descriptor encoder**: a small MLP that maps a **fixed feature vector of the config** (e.g., `[family_onehot, kernel_values, radius, noise_std]`) → conditioning embedding. This enables zero-shot generalization to unseen IDs. **v1 decision**: implement the **config-feature encoder** as the primary conditioning path (so held-out IDs work), with the embedding-table path as an optional ablation.

**Config-feature conditioning vector** (dim = $4 + K_{\max} + 1$):
```
cond_features = concat([
    family_onehot,          # 5
    kernel_padded,          # K_max = 7 (zero-padded to max radius)
    radius,                # 1
    noise_std,              # 1
])
# dim = 5 + 7 + 1 + 1 = 14
```
`cond_encoder = MLP([14, 64, 128])` → 128-dim conditioning embedding $c$.

### 3.4 Denoiser network architecture (small)
The denoiser takes $(z_t \in \mathbb{R}^D, t, c)$ and outputs $\hat\epsilon \in \mathbb{R}^D$. Keep it **small and MLP-based** (weight space has no spatial structure we exploit in v1; the structure is in the *target manifold*, which the model must discover).

**Architecture** (a compact MLP with FiLM-style conditioning):
```
DenoiserNet:
  time_emb: SinusoidalTimeEmbedding(dim=128) -> Linear(128,128) -> SiLU -> Linear(128,128)
  cond_emb: (from cond_encoder) c in R^128
  input: z_t in R^D (D=8352)

  # FiLM modulation per layer
  h = Linear(D, 256)(z_t)
  for block in [256, 256, 256]:
      h = Linear(prev, block)(h) + time_proj(block) + cond_proj(block)   # additive FiLM (v1: additive, not scale-shift, for simplicity)
      h = SiLU(h)
  out = Linear(256, D)(h)
```

**Concrete layers**:
- `fc_in`: Linear(8352, 256)
- 3× residual-ish blocks: Linear(256,256) + time/cond bias, SiLU.
- `fc_out`: Linear(256, 8352)
- Time and cond projections: Linear(128, 256) each, added as bias before activation.

**Parameter count target**:
- `fc_in`: 8352×256 + 256 ≈ 2.14M
- 3 blocks: 3×(256×256 + 256) ≈ 0.20M
- time/cond proj: 2×(128×256 + 256) ≈ 0.066M
- `fc_out`: 256×8352 + 8352 ≈ 2.14M
- `cond_encoder`: 14×64 + 64×128 + ... ≈ 0.017M
- **Total ≈ 4.6M parameters**.

**Sanity check on "smallness"**: the MLP it generates has 8352 params; the diffusion model has ~4.6M. The diffusion model is larger than a *single* MLP, but it is **small relative to the space it models** and, crucially, it is shared across **2000 datasets** — so per-dataset it is ~2300 params, *smaller* than the MLP it generates. The "few parameters" framing is about the model being a **compact shared meta-learner**, not literally smaller than one target. (If a strictly smaller denoiser is desired for v1 ablation, reduce hidden to 128 → ~1.3M params; documented as an ablation knob.)

### 3.5 Timestep embedding
Standard sinusoidal:
$$
\text{te}(t)_{2i} = \sin(t \cdot 10000^{-2i/d}), \quad \text{te}(t)_{2i+1} = \cos(\cdot)
$$
with $d=128$, then 2-layer MLP to 128. Sampled $t \sim \mathcal{U}\{1, T\}$.

### 3.6 Sampling
Standard DDPM 1000-step ancestral sampling (v1). Optional DDIM 50-step for fast eval (documented, not required for v1 success criteria).

## 4. Training Loop

### 4.1 Training data for the diffusion model
For each dataset config in the training corpus:
1. Sample/fix the kernel $k$ (from the config).
2. Build the Toeplitz target MLP weights $\theta$ (Section 2.3).
3. Pack to $\theta \in \mathbb{R}^{8352}$ (Section 2.4).
4. Standardize: $z_0 = (\theta - \mu)/\sigma$ (Section 2.5).
5. Compute conditioning features from the config (Section 3.3).

**Dataset for diffusion training** = list of `(config, z_0)` pairs. Generated once (corpus of 2000) and reused each epoch. Optionally augment by resampling kernels within a family each epoch (v1: fixed corpus for reproducibility; augmentation is a v2 knob).

### 4.2 Diffusion training objective
Standard DDPM noise-prediction MSE:
$$
\mathcal{L}(\phi) = \mathbb{E}_{\text{dataset} \sim \text{corpus}} \mathbb{E}_{t \sim \mathcal{U}(1,T)} \mathbb{E}_{\epsilon \sim \mathcal{N}(0,I)} \left\| \epsilon - \epsilon_\phi\!\left(\sqrt{\bar\alpha_t}\, z_0 + \sqrt{1-\bar\alpha_t}\,\epsilon,\; t,\; \text{cond}(\text{config})\right) \right\|_2^2
$$

### 4.3 Training schedule, optimizer, hyperparameters
| Item | Value |
|------|-------|
| Optimizer | AdamW |
| Learning rate | $1\text{e-}3$, cosine decay to $1\text{e-}5$ |
| Weight decay | $1\text{e-}2$ |
| Batch size | 256 datasets per batch (each contributes one $z_0$) |
| Epochs | 1000 over the corpus (corpus = 2000 → ~128k steps) |
| EMA on denoiser weights | decay 0.9999 (use EMA model for sampling) |
| Gradient clipping | max norm 1.0 |
| $T$ (diffusion steps) | 1000 |
| $\beta$ schedule | linear $[1\text{e-}4, 0.02]$ |
| Precision | float32 (v1); float16 mixed precision optional |
| Logging | TensorBoard: loss, per-dim weight std, EMA loss |

### 4.4 Handling weight scale / variance
- Per-dimension standardization (Section 2.5) ensures $z_0 \approx$ unit variance (where non-constant).
- Constant dimensions (identity/zeros blocks) map to exactly 0 → trivial for the model.
- No per-layer weight normalization inside the denoiser beyond standardization.

### 4.5 Training loop pseudocode
```
for epoch in range(1000):
    for batch_configs in DataLoader(corpus, batch_size=256, shuffle=True):
        z0 = pack_and_standardize(batch_configs)          # [B, D]
        cond = cond_encoder(features(batch_configs))      # [B, 128]
        t = randint(1, T, [B])
        eps = randn([B, D])
        zt = sqrt(bar_alpha[t]) * z0 + sqrt(1-bar_alpha[t]) * eps
        eps_hat = denoiser(zt, t, cond)
        loss = mse(eps, eps_hat)
        optimizer.zero_grad(); loss.backward(); clip_grad_norm_(1.0); optimizer.step()
        ema.update(denoiser)
    cosine_lr.step()
    if epoch % 50 == 0: sample_and_log()   # generate a few, decode, eval on test sets
```

## 5. Evaluation Protocol

### 5.1 Baselines
For each evaluation dataset $X$ (config + its train/test split):

**(a) MLP from scratch**:
- Instantiate `MLPConv` (8352 params, linear, over-parameterized).
- Train with AdamW (lr $1\text{e-}3$, 2000 steps) on the dataset's `n_train` samples, MSE loss on $y$.
- Record train MSE and **test MSE**. This is the no-inductive-bias baseline → expect high test MSE (overfit) when `n_train` is small.

**(b) Convolution**:
- A 1D conv layer with kernel size $K$ (the *true* family kernel size, but **kernel learned from train data**, not given).
- Train with AdamW on `n_train` samples.
- Record train/test MSE. This is the inductive-bias baseline → expect low test MSE.
- Also report **oracle conv** (kernel = ground-truth $k$) as a lower bound.

**(c) Diffusion-generated MLP**:
- Sample $\hat z_0 \sim$ diffusion conditioned on $X$'s config (EMA denoiser, 1000 steps).
- Decode $\hat\theta = \sigma \odot \hat z_0 + \mu$, instantiate `MLPConv`.
- **No further training** (zero-shot weight generation). Evaluate test MSE directly.
- Also report **best-of-$N$** (sample $N=8$, pick lowest-train-MSE one) as a practical variant.

### 5.2 Metrics
| Metric | Definition |
|--------|------------|
| Test MSE | $\frac{1}{|\text{test}|}\sum \|f(x) - y\|^2$ (per-sample, averaged over $L$ positions) |
| Generalization gap | train MSE − test MSE |
| Relative test MSE | test MSE / oracle-conv test MSE (1.0 = perfect conv) |
| Sample efficiency | test MSE vs. `n_train` curve (sweep `n_train` ∈ {16,32,64,128,256}) |
| Param count | MLP: 8352; conv: $K$; diffusion: ~4.6M (shared) |
| Toeplitz-ness score | $\| \hat T - \text{Toeplitzify}(\hat T)\|_F / \|\hat T\|_F$ of the generated `fc2` block (measures whether generated weights are convolution-structured) |

### 5.3 Held-out dataset IDs (meta-generalization)
- **Held-out corpus**: 300 configs with IDs never seen in training.
- For each, run (a), (b), (c). The config-feature conditioning encoder (Section 3.3) enables zero-shot generation for these.
- Report aggregate test MSE (mean ± std over held-out datasets), per family.

### 5.4 Success criteria (quantitative thresholds for v1)
1. **(c) beats (a)**: diffusion-generated MLP test MSE < from-scratch MLP test MSE on **≥ 80%** of held-out datasets, at `n_train = 64`.
2. **(c) approaches (b)**: diffusion test MSE ≤ 1.5× convolution test MSE on **≥ 50%** of held-out datasets.
3. **Toeplitz-ness**: generated `fc2` block Toeplitz-ness score **≤ 0.2** (i.e., generated weights are mostly convolution-structured).
4. **Held-out generalization**: criteria 1–2 hold on held-out IDs, not just train IDs.

### 5.5 Shift-generalization probe (locality stress test)
- Construct a probe input $x^*$ with a **localized bump** (zeros except a Gaussian bump at a random position).
- Evaluate $f(x^*)$ for (a), (b), (c). A convolution produces a translated bump; an overfit MLP produces garbage outside trained positions.
- Metric: correlation of $f(x^*)$ with the translated true bump, across bump positions.

### 5.6 Visualization plan
1. **Loss curves**: diffusion training loss (raw + EMA) vs. steps.
2. **Generated vs. target weights**: for sample datasets, heatmap of $\hat T$ vs. $T_k$ (the `fc2` block), and scatter of $\hat\theta$ vs. $\theta$.
3. **Toeplitz-ness over training**: the Toeplitz-ness score vs. epoch (should decrease).
4. **Sample efficiency**: test MSE vs. `n_train` for (a), (b), (c) — three curves.
5. **Per-family bar chart**: test MSE of (a)/(b)/(c) grouped by family.

## 8. Key Design Decisions Summary

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Target weights source | **Analytic Toeplitz (Approach A)** | Clean meta-learning signal; target IS a convolution; no inner-loop noise |
| MLP architecture | Linear, $L=32, H=128$, 8352 params | Over-parameterized (capacity ✓) but linear so Toeplitz is exact; from-scratch overfits (bias ✗) |
| Toeplitz mapping | Identity in `fc1`, $T_k$ in `fc2` | Target manifold is low-dim (≤7 kernel DOF); easy for diffusion to learn |
| Weight vectorization | Fixed C-order: fc1.w, fc1.b, fc2.w, fc2.b | Deterministic pack/unpack |
| Weight normalization | Per-dim standardize; constant dims → 0 | Diffusion assumes N(0,1); trivial dims reduce effective dimensionality |
| Conditioning | Config-feature encoder (14-dim → 128) | Enables zero-shot on held-out IDs; embedding-table as ablation |
| Diffusion | DDPM, $T=1000$, linear $\beta[1\text{e-}4, 0.02]$, MSE loss | Standard, simple, tractable |
| Denoiser | Compact MLP + FiLM, ~4.6M params | Small shared meta-learner; ~2300 params/dataset < 8352 MLP params |
| Corpus | 2000 train + 300 held-out datasets | Enough to learn the kernel→weight manifold; held-out tests meta-generalization |
| Success threshold | (c) beats (a) on ≥80%, ≤1.5× (b) on ≥50%, Toeplitz-ness ≤0.2 | Concrete, falsifiable v1 criteria |

## 9. Risks and Mitigations

| Risk | Mitigation |
|------|-----------|
| Diffusion model memorizes train IDs, fails on held-out | Config-feature conditioning (not ID table); held-out eval is primary metric |
| Generated weights not Toeplitz enough | Toeplitz-ness metric monitors; can add a Toeplitz-regularization loss in v2 |
| 8352-dim diffusion is slow/unstable | Per-dim standardization; EMA; start with hidden=128 ablation; DDIM for fast eval |
| From-scratch MLP baseline doesn't overfit (phenomenon absent) | Validate in Phase 2 before building diffusion; tune `n_train` to ensure overfitting |
| Linear MLP makes "inductive bias" story less dramatic | v1 isolates the weight-space-structure question; v2 adds ReLU + nonlinear maps for a stronger story |

## 10. v2 Extensions (out of scope for v1, documented for continuity)
- Approach B: learned MLP weights as diffusion targets (per-dataset MLP fitting).
- Nonlinear ground-truth maps + ReLU MLPs.
- Structured input distributions (autoregressive, localized bumps as the *training* distribution).
- Larger $L$ (64, 128) and deeper MLPs.
- DDIM / consistency-model fast sampling.
- Toeplitz-regularized diffusion loss to explicitly enforce convolution structure.
- Cross-family meta-generalization (train on 4 families, test on 1 held-out family).
